## O que é o Easy Labs

O `easy-labs` é o repositório central de contexto do ecossistema. Não contém código de produto — serve como **memória compartilhada** entre desenvolvedores humanos e agentes de IA (Claude Code) que trabalham nos projetos.

É onde ficam:

| O que | Onde | Para quê |
|-------|------|----------|
| Tarefas ativas por repo | `context/[repo]/active.md` | Retomar trabalho sem perder contexto |
| Regras técnicas por repo | `context/[repo]/CLAUDE.md` | Orientar o agente antes de codar |
| Roadmap ativo | `roadmap/CURRENT.md` | Prioridades e estado do que está em desenvolvimento |
| Histórico de sessões | `memory/sessions/` | O que foi feito, quando e por quê |
| Decisões arquiteturais | `memory/decisions/` | ADRs numerados para decisões recorrentes |
| Runbooks | `runbooks/` | Passo a passo para tarefas padronizadas |
| Interface visual | `ui/` | Dashboard, canvas e session planner |

## Estrutura atual

```
easy-labs/
├── START_HERE.md          ← protocolo de início de sessão
├── PIPELINE.md            ← esteira PLAN → DISCUSS → EXECUTE → VALIDATE
├── ECOSYSTEM.md           ← mapa dos repositórios e dependências
├── easy-labs-config.json  ← configuração do workspace
├── context/
│   └── [repo]/
│       ├── active.md      ← tarefas acionáveis (máx 60 linhas)
│       └── CLAUDE.md      ← regras técnicas para agentes de IA
├── memory/
│   ├── INDEX.md           ← índice de toda a memória
│   ├── sessions/          ← histórico por sessão (YYYY-MM-DD-sNN.md)
│   └── decisions/         ← ADRs numerados
├── roadmap/
│   ├── CURRENT.md         ← etapas ativas e em execução
│   ├── BACKLOG.md         ← próximas etapas
│   └── DONE.md            ← histórico concluído
├── runbooks/              ← guias de execução
├── templates/             ← templates de sessão e subagente
└── ui/                    ← interface visual (Next.js)
```

## Pipeline obrigatório

Todo trabalho nos repos segue a esteira:

```
PLAN → DISCUSS → EXECUTE → VALIDATE
```

| Etapa | O que fazer |
|-------|------------|
| **PLAN** | Ler `context/[repo]/active.md` + seção ativa do `roadmap/CURRENT.md` |
| **DISCUSS** | Alinhar spec, mapear arquivos afetados, decidir commits |
| **EXECUTE** | Implementar no repo de produto com commits atômicos |
| **VALIDATE** | Verificar build, atualizar `active.md`, commitar easy-labs |

## Como iniciar uma sessão

```bash
# No terminal, iniciando com contexto mínimo
claude --model sonnet "
Leia context/app-front/active.md e roadmap/CURRENT.md (seção Em execução agora).
Siga PIPELINE.md. Tarefa: [descrever o que fazer]
"
```

Ou use o **Session Planner** da interface visual para montar esse comando automaticamente.

## Como encerrar uma sessão

1. Atualizar `context/[repo]/active.md` — marcar `[x]`, adicionar novos bloqueadores
2. Criar `memory/sessions/YYYY-MM-DD-sNN.md` usando o template
3. Atualizar `roadmap/CURRENT.md` se itens foram concluídos
4. Commitar:

```bash
cd easy-labs
git add .
git commit -m "chore: atualizar contexto — s{N} descrição curta"
```

## Orçamento de tokens por sessão

| Cenário | Arquivos lidos | Tokens estimados |
|---------|---------------|-----------------|
| Continuando trabalho | active.md + CURRENT.md (seção ativa) | ~600 |
| Cold start | ECOSYSTEM + active.md + CURRENT.md + última sessão | ~1.000 |
| Bug fix | CLAUDE.md + ADR relevante | ~650 |
| Subagente | Trecho do CLAUDE.md + escopo da tarefa | ≤ 800 |

<Tip>
Use `active.md` (máx 60 linhas) como fonte principal. Nunca passe o arquivo inteiro para subagentes — recorte apenas a seção relevante.
</Tip>
