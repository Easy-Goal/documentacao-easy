## Objetivo

Última etapa antes da publicação. Valida que o produto funciona corretamente em ambiente de produção/staging, com credenciais de teste para o time de review.

## Fluxo no Typebot

<Steps>
  <Step title="URLs do Ambiente">
    - URL de produção → `production_url`
    - URL de staging/teste (opcional) → `staging_url`
  </Step>
  <Step title="Credenciais de Teste">
    - Email de acesso para teste do admin → `admin_test_email`
    - Senha de acesso para teste → `admin_test_password`
    - Instruções adicionais de acesso (opcional) → `access_instructions`
  </Step>
  <Step title="QA Checklist">
    Checkboxes de validação:
    - Login via SSO EasyGoal funciona
    - Página do produto carrega sem erros
    - Checkout/pagamento funciona (se aplicável)
    - Dados do usuário são exibidos corretamente após login
    - Logout funciona e redireciona corretamente
    - Responsivo em mobile
    - SSL/HTTPS configurado

    → variável `qa_checklist`
  </Step>
  <Step title="Problemas Conhecidos">
    Input de texto longo: problemas conhecidos ou limitações (opcional) → `known_issues`
  </Step>
  <Step title="Disponibilidade">
    Botões: Já está pronto | Em 1 semana | Em 2 semanas | Em 1 mês → `availability`
  </Step>
  <Step title="Observações Finais">
    Input de texto longo: observações adicionais para o time de review (opcional) → `final_notes`
  </Step>
</Steps>

## O que acontece após o Step 4

```
Admin recebe notificação
   ↓
Admin testa o produto com as credenciais fornecidas
   ↓
Admin homologa (todos os checks OK?)
   ↓
[Produto aprovado] → GA4 + GTM provisionados automaticamente → Publicado no marketplace
   ↓
Produtor recebe notificação de publicação
```

<Tip>
O time de review entra em contato em até **48h úteis** após a conclusão de todos os steps. Você pode acompanhar o progresso no painel de produtor.
</Tip>

## Botão "Testar GA4" (Admin)

Após a aprovação, o admin pode validar que os eventos de analytics estão chegando corretamente no GA4 do produto via painel admin (`/admin/saas-products/[id]`):

- **Testar GA4** — envia um evento `purchase` de teste ao GA4 do produto. Use para confirmar que a propriedade foi provisionada corretamente e que os dados aparecem no DebugView do GA4.
- **Abrir GA4** — abre o painel GA4 do produto diretamente.
- **Sincronizar Property ID** — visível apenas quando `ga4_measurement_id` existe mas `ga4_property_id` está ausente; backfill manual do ID numérico da propriedade.

<Note>
O Analytics (GA4 + GTM) é provisionado automaticamente ao aprovar o produto. Não é necessário nenhuma ação do produtor para configurar rastreamento.
</Note>

## Fluxo de Comentários Admin ↔ Produtor

Os comentários são o canal de comunicação por step entre admin e produtor:

1. Admin adiciona comentário no step identificando ajustes necessários
2. Produtor recebe notificação (badge + email futuro)
3. Step mostra badge "Ajustes solicitados"
4. Produtor acessa o step, vê o comentário e corrige
5. Produtor responde no comentário
6. Admin marca como resolvido
7. Step retorna ao fluxo normal

O botão **"Solicitar Ajustes"** marca `has_pending_changes = true` no step. Use quando o produtor precisa refazer algo no Typebot e o step não pode ser aprovado no estado atual.
