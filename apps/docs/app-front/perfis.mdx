## Sistema de perfis

O app [app.easygoal.com.br](https://app.easygoal.com.br) define o perfil por flags no registro do usuário, avaliadas logo após o login.

<Columns cols={3}>
  <Card title="Cliente" icon="user">
    Perfil padrão. Acompanha entregáveis e faturas.
  </Card>
  <Card title="Builder" icon="store">
    Quem constrói com a Easy Goal. No app, aparece como perfil de Produtor. Vê a área do cliente e a gestão dos próprios SaaS.
  </Card>
  <Card title="Admin" icon="shield">
    Equipe interna da Easy Goal. Administra usuários, empresas, builders e produtos.
  </Card>
</Columns>

---

## Como os perfis são determinados

| Flag | Valor | Perfil resultante |
|------|-------|-------------------|
| Super admin | ativa | **Admin**, com acesso apenas à área admin |
| Produtor | ativa | **Builder**, com área de produtor e área do cliente |
| Nenhuma das duas | — | **Cliente** |

<Note>
  Um super admin não vê o menu de cliente ou de builder. A área de gestão não se mistura com a navegação de cliente.
</Note>

---

## Hierarquia de acesso

```
Admin (is_super_admin = true)
├── Gestão de usuários, empresas e builders
├── Aprovação de produtos
└── Sistema (configurações, admins, logs)

Builder (is_producer = true)
├── Área do cliente
└── Meus SaaS, roadmap, eventos e guias

Cliente (padrão)
├── Dashboard
├── Entregáveis
└── Faturas
```

## Como um builder entra

Builders entram por convite ou pelo desafio.

<Steps>
  <Step title="Convite ou desafio">
    O builder recebe um convite da equipe Easy Goal ou chega pelo desafio.
  </Step>
  <Step title="Cadastro pelo admin">
    Um administrador cria o registro de produtor, vinculado ao usuário e à empresa.
  </Step>
  <Step title="Aceite">
    O builder aceita o convite em `/invitation` e completa os dados.
  </Step>
  <Step title="Verificação">
    O admin altera o status de `pending` para `verified`. A partir daí, o menu de produtor aparece no sidebar.
  </Step>
</Steps>

Status possíveis: `pending` · `verified` · `suspended` · `rejected`
