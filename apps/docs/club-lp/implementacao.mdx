<Note>
O Club LP não implementa OAuth manualmente — todo o fluxo (login, callback, sessão) é encapsulado pelo pacote `@easygoal/packages/auth`. O código abaixo é um exemplo de referência do padrão usado — adapte os caminhos de arquivo à estrutura do seu próprio projeto.
</Note>

## 1. Provider de sessão

Envolve a aplicação com o `EgSessionProvider`, que disponibiliza `useEgSession()` para qualquer componente client-side:

```tsx
// src/providers/EasyGoalProvider.tsx
'use client';

import { EgSessionProvider } from '@easygoal/packages/auth/client';

export function EasyGoalProvider({ children }: { children: React.ReactNode }) {
  return <EgSessionProvider>{children}</EgSessionProvider>;
}
```

## 2. Botão de login

O login é disparado client-side com o hook `useSSOLogin`, que redireciona para o SSO passando `redirect_to` (não `redirect_uri`) e a API key do produto:

```tsx
// src/components/Navbar.tsx
'use client';

import { useSSOLogin } from '@easygoal/packages/auth/client';

const SSO_URL = process.env.NEXT_PUBLIC_SSO_URL!;
const API_KEY = process.env.NEXT_PUBLIC_EASY_API_KEY!;

function LoginCTA() {
  const { login } = useSSOLogin({
    ssoUrl: SSO_URL,
    apiKey: API_KEY,
    callbackPath: '/auth/callback',
  });

  return (
    <button onClick={login} className="rounded-lg bg-orange-500 px-4 py-2 text-sm font-semibold text-white">
      Entrar
    </button>
  );
}
```

## 3. Callback

Recebe `?eg_session=<token>` (e opcionalmente `?next=<path>`) do SSO e salva o token em um cookie httpOnly por 7 dias:

```ts
// src/app/auth/callback/route.ts
import { NextRequest, NextResponse } from 'next/server';

const COOKIE_OPTIONS = {
  httpOnly: true,
  secure: process.env.NODE_ENV === 'production',
  sameSite: 'lax' as const,
  path: '/',
  maxAge: 60 * 60 * 24 * 7, // 7 dias
};

export async function GET(request: NextRequest) {
  const { searchParams } = request.nextUrl;
  const next = searchParams.get('next') ?? '/';
  const redirectPath = next.startsWith('/') ? next : '/';

  const egSession = searchParams.get('eg_session');
  if (egSession) {
    const response = NextResponse.redirect(new URL(redirectPath, request.url));
    response.cookies.set('eg_session', egSession, COOKIE_OPTIONS);
    return response;
  }

  return NextResponse.redirect(new URL('/', request.url));
}
```

Não há `access_token`, `refresh_token`, `state` nem cookie `oauth_state` nesse fluxo — apenas o `eg_session` já assinado pelo SSO.

## 4. Endpoint de sessão

Decodifica o payload do `eg_session` (sem verificar assinatura — a verificação já foi feita pelo SSO ao emitir o token) e devolve os claims para o `EgSessionProvider` consumir:

```ts
// src/app/api/auth/session/route.ts
import { cookies } from 'next/headers';
import { NextResponse } from 'next/server';

export const dynamic = 'force-dynamic';

export async function GET() {
  const cookieStore = await cookies();
  const raw = cookieStore.get('eg_session')?.value;

  if (raw) {
    try {
      const payloadBase64 = raw.split('.')[1];
      const payload = JSON.parse(Buffer.from(payloadBase64, 'base64url').toString('utf8'));
      return NextResponse.json(payload);
    } catch {
      // cai para o 401 abaixo
    }
  }

  return NextResponse.json({ error: 'unauthorized', reason: 'missing_session' }, { status: 401 });
}
```

## 5. Logout

```ts
// src/app/api/auth/signout/route.ts
import { handleSignout } from '@easygoal/packages/auth/server';
import type { NextRequest } from 'next/server';

export async function POST(request: NextRequest) {
  return handleSignout();
}
```

## 6. Banner com dados do usuário

Não existe uma página `/profile` dedicada — os dados do usuário aparecem em um banner fixo na própria landing page, lido via `useEgSession()`:

```tsx
// src/components/AuthBanner.tsx
'use client';

import { useEgSession } from '@easygoal/packages/auth/client';

export function AuthBanner() {
  const { user, isReady } = useEgSession();

  if (!isReady || !user) return null;

  return (
    <div className="fixed top-0 left-0 right-0 z-50 bg-card border-b border-border px-4 py-2.5">
      Olá, {user.name ?? user.email}!
      {user.isProducer && ' Você é um produtor Easy Goal.'}
    </div>
  );
}
```

`user.isProducer` e `user.companyName` vêm diretamente dos claims `is_producer` e `company_name` do `eg_session` — veja [SSO — Visão Geral](/sso/visao-geral) para a lista completa de claims.
