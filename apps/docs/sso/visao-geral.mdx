## O que é o SSO EasyGoal?

O SSO (Single Sign-On) é o serviço de autenticação centralizado do ecossistema Easy Goal. Ele:

- Autentica usuários usando **Supabase Auth** (email/senha + OAuth Google, GitHub, Azure/Microsoft)
- Emite sessões Supabase que outros apps do ecossistema reutilizam
- Recebe webhooks do **app-front** quando um pagamento é confirmado
- Redireciona de volta para o app solicitante via parâmetro `redirect_to`

## Como funciona a autenticação cross-domain

```
[app-front] detecta sem sessão Supabase
    ↓
Redireciona para SSO: {SSO_URL}/auth/login?redirect_to=<callback_url>
    ↓
SSO autentica via Supabase, obtém access_token + refresh_token
    ↓
SSO retorna tokens via redirect para callback_url
    ↓
[app-front /auth/callback] recebe tokens, estabelece sessão Supabase local
    ↓
Redireciona para /dashboard
```

<Note>
O parâmetro de redirect é `redirect_to` (não `redirect_uri`). Use sempre `redirect_to` ao construir URLs de redirecionamento para o SSO.
</Note>

## Integração via @easygoal/auth (recomendado)

Para conectar um app Next.js ao SSO, use o package `@easygoal/auth`. Ele encapsula o `AuthProvider`, callback route, middleware e hook de sessão.

```bash
npm install github:easygoal/easygoal-ui#main
```

Veja a documentação completa de instalação e uso em [Monorepo → Setup & Instalação](/monorepo/setup).

## Variáveis de Ambiente do SSO

```env
# Supabase (mesma instância compartilhada com o app-front)
NEXT_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key

# URLs
NEXT_PUBLIC_APP_URL=http://localhost:3000

# Webhook — DEVE ser idêntico ao SSO_WEBHOOK_SECRET do app-front
WEBHOOK_SECRET=your-webhook-secret-key

# Email
RESEND_API_KEY=your-resend-api-key
```

<Warning>
`WEBHOOK_SECRET` (SSO) e `SSO_WEBHOOK_SECRET` (app-front) devem ser **idênticos**. Qualquer divergência fará com que todos os webhooks sejam rejeitados com status 401.
</Warning>

## Endpoints do SSO

| Método | Endpoint | Descrição |
|--------|----------|-----------|
| `GET` | `/auth/login` | Formulário de login — aceita `?redirect_to=<url>` |
| `GET` | `/auth/signup` | Criar conta |
| `GET` | `/auth/forgot-password` | Solicitar reset de senha |
| `GET` | `/auth/reset-password` | Redefinir senha (via link de email) |
| `GET/POST` | `/auth/callback` | Callback OAuth do Supabase |
| `POST` | `/auth/signout` | Logout — invalida sessão Supabase |
| `GET` | `/auth/error` | Página de erro de autenticação |
| `GET` | `/complete-profile` | Completar perfil após OAuth |
| `GET` | `/dashboard` | Dashboard do usuário no SSO |
| `POST` | `/api/webhook/payment` | Recebe notificação de compra (HMAC SHA256) |
| `GET` | `/api/webhook/payment` | Health check do endpoint |
| `GET` | `/api/plans/public` | Planos disponíveis (público) |

## Checklist do SSO

<Check>Configurar `WEBHOOK_SECRET` (= `SSO_WEBHOOK_SECRET` do app-front)</Check>
<Check>Configurar `NEXT_PUBLIC_SUPABASE_URL` e `NEXT_PUBLIC_SUPABASE_ANON_KEY`</Check>
<Check>Adicionar URLs de redirect em Supabase → Auth → URL Configuration</Check>
<Check>Registrar URLs de callback em Supabase → Auth → Redirect URLs</Check>
<Check>Implementar `POST /api/webhook/payment` com verificação HMAC SHA256</Check>
<Check>Testar webhook com o botão "Testar Webhook" no admin do app-front</Check>
